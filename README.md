# Авито-монитор

Личный Telegram-бот для новых объявлений о комплектующих и компьютерах. Работает на домашнем ПК: Chrome получает доступную выдачу Авито, фильтры выбирают объявления, отдельная очередь отправляет их владельцу и приглашённым участникам.

Скорость появления объявления в поиске зависит от Авито. Доставку за 60 секунд от публикации и работу без капчи бот не гарантирует.

## Установка на новый компьютер

1. Создайте бота через [BotFather](https://t.me/BotFather). Один токен используйте только на одном компьютере.
2. Скопируйте проект без `.env`, `data/` и `.venv/`.
3. Установите Google Chrome и запустите `start.bat` на Windows, `start.command` на macOS или `./start.sh` на Linux. Скрипт установит uv, Python, зависимости и Chromium. По умолчанию используется Chrome; для управляемого Chromium явно задайте `BROWSER_CHANNEL=chromium`. Автоматического переключения браузера при ошибке нет.
4. Мастер спросит токен, город и **числовой Telegram ID владельца**. Первый посторонний `/start` больше не может назначить владельца. У существующей установки сохраняется ID из SQLite.
5. Отправьте своему боту `/start`, добавьте запросы через меню. Запросы и уведомления общие для всех приглашённых участников.

Повторная настройка: `uv run avito-setup`. Обычный запуск: `uv run avito-supervise`. Контроллер перезапускает приложение после любого сбоя с паузами от 10 секунд до 10 минут, без предела попыток; зависание цикла сбора или доставки обнаруживает watchdog. Нормальное завершение и ошибка конфигурации останавливают контроллер.

## Ограничения Авито и автоматическое восстановление

Паузы и команды `/resume` нет: бот сам продолжает сбор, когда Авито это разрешает. Подробно — [docs/autonomy.md](docs/autonomy.md).

- **429:** срок `Retry-After` соблюдается полностью. Без него действует локальная пауза `COOLDOWN_SECONDS`, удваивающаяся при повторах до `MAX_BACKOFF_SECONDS`. После срока сбор продолжается сам, без команд. О каждом новом 429 приходит уведомление.
- **429 «Доступ ограничен: проблема с IP»:** окно Chrome бота разворачивается со страницей проверки. Нажмите «Продолжить» и пройдите её — сбор продолжится сразу (или после срока Авито, если он указан). После 429 на лёгкий запрос следующая проверка делается обычной загрузкой страницы, чтобы проверка была видна. Интервал опроса случайно меняется на ±30 % (`POLL_JITTER`).
- **Капча:** источник переходит в `VERIFICATION_REQUIRED`, запросы прекращаются. Пройдите проверку в окне Chrome бота: бот сам увидит обычную выдачу на открытой странице (без нового запроса) и продолжит сбор. Если Авито указал срок, сбор начнётся после него.
- **Доступ есть — сбор идёт:** любая пауза бота (после 429, капчи, 403, ошибки сети) заканчивается, как только в окне Chrome бота видна обычная выдача Авито. Чтобы продолжить сразу, отправьте `/unblock`: бот один раз загрузит страницу, при проверке пройдите её. Срок `Retry-After` от Авито так не сокращается.
- **403:** `ACCESS_DENIED`, повторов вслепую нет. Доступ восстанавливается обычной выдачей в окне Chrome или по `/unblock` — одной загрузке по вашему запросу.
- **Перезапуск и смена движка:** сохранённые сроки из SQLite остаются в силе. При запуске бот один раз сообщает, что это состояние из базы, а не ответ текущего браузера.
- **Закрытый или упавший Chrome** перезапускается автоматически; ограничения при этом не сбрасываются. Telegram и очередь работают независимо от источника.
- Во время ограничений и до первой подтверждённой выдачи текущего запуска уведомления идут без скачивания фотографий с Авито.
- Нет активных подписок — нет запросов к Авито.

Для проверки при остановленном боте: `uv run avito-unblock`. Команда использует тот же профиль и блокировку единственного экземпляра. Не запускайте её параллельно с работающим ботом.

## Надёжность доставки

SQLite атомарно сохраняет новое объявление, `seen` и задания для каждого получателя. Независимый отправитель повторяет временные ошибки Telegram, учитывает `Retry-After` и подтверждает каждое успешное сообщение. Запрет общения с ботом и неисправимые запросы остаются видимыми в очереди как `terminal`. Удалённым участникам задания не отправляются.

Фотография объявления переиспользуется в ограниченном кэше памяти при отправке нескольким получателям. Это сокращает повторные обращения за одной картинкой; ошибки загрузки и пустые ответы не кэшируются. Кэш очищается при перезапуске и не записывается на диск.

Гарантия доставки — **at-least-once**: при падении между успешным ответом Telegram и записью подтверждения возможен редкий дубль. Подтверждённые задания повторно не отправляются. Прежние счётчики до миграции сохраняются как исторические; новые счётчики увеличиваются только после успешного ответа Telegram.

Первая загрузка новой ленты создаёт исходный снимок и не рассылает уже существующие объявления. Поиск обрабатывает только доступный снимок выдачи: при отсутствии пересечения соседних снимков бот предупреждает о возможных пропусках и не добавляет запросы автоматически.

## Состояние и метрики

`/health` раздельно показывает сервис, источник и доставку Telegram, ограничения с причиной и сроком, очередь `pending/leased/retry/sent/terminal`, сводку за 24 часа и p50/p95 доставки. `/recent` — последние находки и изменения цен, `/errors` — история ограничений и сбоев. `/add` принимает готовую ссылку поиска Авито. Раз в сутки приходит отчёт. Открывать проверку (`/unblock`) может только владелец.

- `data/bot.sqlite3`: исходные таблицы и добавленные `items`, `notification_outbox`, `source_state`, `fetch_metrics`, `events`, `price_history`.
- `data/bot.log`: журнал с ротацией; `data/items.jsonl`: новые объявления для диагностики.
- `uv run avito-metrics`: последние результаты опросов в JSON.
- `uv run avito-metrics --compare`: JSON `schema_version=2`. Четыре конфигурации показаны в `groups`, первоначальные загрузки — в `warmup`, обычные проверки — в `regular_by_actual_mode` и `mechanisms`. `total_load` включает записанную нагрузку ручных открытий и warm-up. Для сравнения выбирайте одинаковые `cohorts`; старые записи без известного этапа исключены из сравнения повторных проверок. Команда не делает сетевых запросов.
- `uv run avito-metrics --availability`: время работы сервиса и отдельно доступность источника, 403/429, восстановления, доставка и трафик по таблице событий.
- `uv run avito-metrics --events > data/events.csv`: публикация, обнаружение, подтверждённая доставка и состояние задания для сравнения источников. Чаты в экспорт не включаются.

Сводка `/health` считает последние 5000 доставок получателям, а не уникальные объявления. Внутренняя цель обнаружение→Telegram p95 ≤10 секунд измеряется отдельно от публикация→Telegram. Для выводов нужна длительная выборка.

## Настройки

Образец — `.env.example`. Переменные окружения имеют приоритет над `.env`.

| Параметр | Назначение |
|---|---|
| `BOT_TOKEN`, `OWNER_ID` | Токен и числовой ID владельца. Legacy ID из базы поддерживается |
| `CITY` | Город по умолчанию, например `kazan` |
| `FEED`, `SECTIONS` | Одна лента на город и нужные разделы внутри неё |
| `REQUESTS_PER_MINUTE` | Общий бюджет лент для всех городов, по умолчанию 1/мин; дробные значения допустимы |
| `NIGHT_REQUESTS_PER_MINUTE`, `NIGHT_HOURS` | Ночной бюджет и часы по локальному времени ПК; поддерживается интервал через полночь |
| `COOLDOWN_SECONDS`, `MAX_BACKOFF_SECONDS` | Локальная пауза после 429 без `Retry-After` (900 с) и её потолок при удвоении (21600 с). Срок Авито соблюдается отдельно |
| `VERIFICATION_CHECK_SECONDS` | Как часто читать открытую страницу при ожидании проверки, без запросов (5 с) |
| `WATCHDOG_SECONDS` | Через сколько секунд без признаков работы процесс перезапускается (600) |
| `PRICE_DROP_PERCENT` | Порог уведомления о снижении цены, % (10; 0 — выключено) |
| `DAILY_REPORT_HOUR` | Час ежедневного отчёта (9; −1 — выключено) |
| `POLL_JITTER` | Случайный разброс интервала проверки, доля (0.3 = ±30 %; 0 — без разброса) |
| `DIRECT_INTERFACE` | Интерфейс/локальный IP домашней сети, если нужен прямой маршрут при VPN |
| `HEADLESS` | По умолчанию 0, обычное окно браузера |
| `BROWSER_ENGINE` | `playwright` по умолчанию; `patchright` требует extra `experimental` |
| `FETCH_MODE` | `light_fetch` по умолчанию: после первой навигации fetch HTML; `page_navigation`: обычная навигация при каждой проверке |
| `BROWSER_CHANNEL` | `chrome` по умолчанию или явно выбранный `chromium`; ошибка запуска не меняет выбор |
| `SAVE_DEBUG_HTML` | По умолчанию 0. При 1 — один обезличенный образец структуры, без полного HTML и скриптов |
| `DEBUG_HTML_RETENTION_HOURS` | Срок хранения образца, по умолчанию 24 часа; удаление проверяется также во время ограничений |

Профили браузера и `.env` не публикуются. Каталог `data/` доступен только владельцу ОС. Прямой прокси привязывает сокет к указанной сети; он не гарантирует отсутствие ограничений Авито.

Patchright использует отдельный профиль, без переноса cookies. Ограничения, общий бюджет городов, SQLite и Outbox едины для обоих движков. [Установка на macOS/Windows/Linux, ручное переключение, возврат и методика сравнения](docs/browser-experiment.md). Основной режим остаётся Playwright + light_fetch; длительный эксперимент запускается только вручную.

## Фоновый запуск на macOS

После проверки новой версии:

```sh
uv sync --frozen
uv run pytest -q
uv run avito-service install
uv run avito-service status
```

`install` удерживает отдельную `data/deployment.lock` на всём протяжении установки: останавливает прежний LaunchAgent, дожидается выгрузки и освобождения `bot.lock`, создаёт согласованную копию SQLite в `data/backups/`, готовит plist и запускает службу `local.avito-monitor`. Второй установщик не может остановить или заменить службу, пока первый не завершил операцию.

После регистрации проверяются процесс supervisor и свежая диагностика готовности дочернего Python-приложения. Код выхода 0 и `status=ready` означают подтверждённый запуск; код 2 и `status=registered` — только регистрацию с работающим процессом, без подтверждения готовности за 30 секунд. Ошибка даёт код 1, сохраняет прежний `deployment.json` и записывает `status=failed` с причиной в `data/deployment-attempt.json`. Результаты записываются атомарно. Ограничение Авито `WAITING_FOR_USER` само по себе не мешает готовности приложения.

При входе пользователя служба запускается снова. `KeepAlive` отключён, поэтому macOS не создаёт дополнительную бесконечную петлю перезапусков. Токен читается из `.env`, в plist не копируется.

Остановка: `uv run avito-service stop`. Фоновый запуск не предотвращает сон компьютера: для непрерывной работы настройте питание macOS или используйте обычный `start.command` с `caffeinate`.

Миграция и откат: [инструкция](docs/reliability-rollout.md). Архитектура и выполнение ревью: [план](docs/reliability-plan.md). Исторические замеры предыдущей версии — [техническая записка](docs/tech-report.html).

## Разработка

Python 3.12+, aiogram 3, Playwright, SQLite, httpx. `Source`/`FetchResult` отделены от планировщика и Telegram; новый API-поставщик должен реализовать этот контракт. Поставщик не включается без подтверждённых условий доступа и измерений.

```sh
uv sync --frozen
uv run pytest -q
```

Полная проверка экспериментального движка: `uv sync --frozen --extra experimental`, затем `uv run --extra experimental pytest -q`. Установка extra сама по себе не меняет выбранный движок. Точный `uv sync --frozen` удаляет extra; при использовании Patchright сохраняйте `--extra experimental` в командах синхронизации.

HTML-тесты запускают локальный headless Chromium/Chrome. Все их запросы перехватываются фикстурами; обращений к Авито нет. Если браузер ещё не установлен: `uv run playwright install chromium`.

## Суточное наблюдение локального канала

Сторонние API/webhook в текущем режиме не используются. `uv run avito-study start --hours 24` включает пассивное измерение текущего источника без дополнительных обращений к Авито. `/health` показывает срок окончания. Промежуточный отчёт: `uv run avito-study report`; итоговые файлы автоматически сохраняются в `data/studies/<id>/`.

После второй подряд HTTP 429 автоматический опрос останавливается до ручного действия владельца, с соблюдением срока ожидания. Эксперимент его не возобновляет. Периоды выключенного приложения не считаются успешной работой источника, а пустая выборка не считается подтверждённым SLA. [Описание измерений](docs/local-study.md).

Первое окно наблюдения завершено: [результаты 24–25 октября 2026](docs/results/2026-10-25-local-study.md). Успешных выдач не было; скорость и полнота не подтверждены.
