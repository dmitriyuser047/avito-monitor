# Установка обновления и откат

Обновление добавляет таблицы и индексы, включает SQLite WAL и busy_timeout. Старые subscriptions/settings/seen/members/invites/notifications сохраняются. Профиль браузера и токен используются прежние. Файлы `-wal` и `-shm` нельзя удалять у работающего SQLite.

## Перед установкой

Остановить прежний экземпляр через его окно или `uv run avito-service stop`. Запустить `uv sync --frozen` и `uv run pytest -q`. Для ручного запуска предварительно создать согласованную копию через SQLite backup API; обычное копирование одного файла у работающей WAL-базы недостаточно.

На macOS `uv run avito-service install` сам проверяет отсутствие второго экземпляра и создаёт копию через backup API с проверкой integrity_check. Копия хранится в `data/backups/`, её путь и установленный коммит — в `data/deployment.json`. Только затем запускается новая версия, выполняющая добавляющую миграцию.

## Проверка после установки

1. `uv run avito-service status` показывает работающую службу. `data/bot.log` содержит Application ready и состояние источника. Отдельно проверить Telegram polling и отсутствие конфликтов второго экземпляра.
2. В Telegram открыть `/health`: очередь видна, статус и причина ограничения соответствуют журналу. При WAITING_FOR_USER никаких автоматических повторов не должно быть.
3. Сверить количество старых подписок, участников, settings и seen с резервной копией. Новые объявления могут увеличить seen после старта; уменьшения и удаления старых записей не ожидаются, кроме штатной очистки seen старше 30 дней.
4. При доступной выдаче дождаться одного обычного цикла. Если Авито просит проверку, оставить сбор остановленным; владелец использует /unblock и /resume. Не проходить капчу автоматически.
5. Непрерывность и задержку оценивать после достаточного времени наблюдения. Развёртывание не является доказательством суточной устойчивости.

## Откат

1. `uv run avito-service stop` и убедиться, что процесс приложения завершился.
2. Создать новую согласованную backup-копию текущей БД, включая незавершённый outbox. **Не восстанавливать старую копию поверх новой автоматически**: иначе будут потеряны задания после обновления.
3. Вернуться к исходному коммиту `add11854a670ffbb95b7fcbe2592b0ee5f9db8cc` в отдельной ветке/checkout и выполнить `uv sync --frozen`. Новые таблицы старому коду не мешают. Если запускать старый код с новой базой, учесть: старая версия не отправляет outbox и может потерять новые уведомления при сбоях. Для надёжной доставки сначала завершить очередь новой версией либо сохранить её для последующего восстановления.
4. Старую версию запускать её штатным способом; команды avito-service в исходном коммите нет. Автозапуск LaunchAgent до обратного обновления отключить командой `launchctl bootout gui/$(id -u)/local.avito-monitor`.

Для восстановления повреждённой БД использовать проверенную backup-копию только после остановки всех экземпляров. Сохранить исходную повреждённую базу и её WAL рядом для расследования и извлечения заданий.

## Одновременные запуски и завершение

Приложение и отдельный avito-unblock используют один OS lock. Второй экземпляр прекращает запуск с кодом 78. Telegram, источник и worker завершаются с отменой asyncio-задач и закрытием сетевых клиентов/SQLite. После неожиданного падения незавершённые lease возвращаются в retry по истечении 120 секунд. После подтверждённого sent повторной отправки нет.
