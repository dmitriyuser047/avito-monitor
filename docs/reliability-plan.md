# План повышения надёжности

Основа — ревью от 24 октября 2026 для коммита add1185. Изменения выполняются в ветке `codex/reliability-v2`. Исходные 23 теста прошли; перед изменениями создана копия SQLite в `data/backups/`. Подписки, участники, настройки, приглашения и просмотренные ID сохраняются.

## Этапы реализации

1. Транзакционный outbox и независимый отправитель. Задания имеют состояния pending/leased/retry/sent/terminal, уникальность по объявлению и чату, снимок полезной нагрузки и восстановление lease. Статистика новых событий учитывает подтверждённую отправку.
2. Контракт источника, отдельный планировщик, сохранённые состояния ограничения и единый бюджет всех городов. При 403/капче автоматический опрос останавливается до ручного действия, при 429 учитывается Retry-After. Никакой автоматической полной загрузки вслед за отказом лёгкого запроса.
3. Жизненный цикл, назначение владельца и ограничение рестартов. Браузер проверяется на паузе; его остановка не отключает Telegram. Сохранённый владелец поддерживается, автоматического назначения по первому /start нет.
4. Диагностика и контроль качества. /health, фактические интервалы, снимки ID и предупреждение о возможных пропусках, задержки публикация/обнаружение/доставка, обезличенные диагностические образцы с TTL.
5. Проверки миграции и сбоев, обновлённая инструкция, резервная копия перед установкой, локальный деплой через LaunchAgent и проверка состояния.

## Границы проверки

Доставка имеет семантику at-least-once. Сбой между Telegram success и SQLite ack может привести к редкому повтору. Терминальные задания остаются видимыми; их нельзя автоматически считать успешными. Историческая таблица notifications сохраняется без попытки задним числом доказать доставку старых сообщений.

Часы задержки опубликовано→доставлено и обнаружено→доставлено разделены. Первая метрика зависит от индексации Авито; обещание 60 секунд не вводится. Пересечение снимков обнаруживает возможный разрыв, но само по себе не доказывает полноту выдачи.

## Проверка альтернативного источника в первоначальном плане

Проверка официального каталога https://developers.avito.ru/api-catalog через доступный веб-инструмент не вернула содержимое. Поэтому наличие разрешённого API поиска чужих объявлений или webhook в этой работе не подтверждено. Сторонний канал не подключён: нет предоставленного договора, ключа и подтверждённого права на данные. Контракт Source позволяет добавить адаптер без изменений matcher/UI.

Уведомления сохранённого поиска рассматриваются только как кандидат для ручного сравнения. Их скорость и полнота здесь не измерены. Для пилота нужно задать те же фильтры, получить разрешённый доступ, записать ID, публикацию, появление у источника, доставку и паузы минимум за 24 часа. Экспорт текущего канала доступен через `avito-metrics --events`. Сравнивать p50/p95, долю ≤60 секунд, пересечение ID, ограничения и стоимость. Автоматическую капчу, ротацию профилей/IP и подмену отпечатков не внедрять.

Подключение поставщика и суточный эксперимент — условный внешний этап, а не выполненный тест. Без доступа к поставщику его нельзя достоверно завершить; локальные программные изменения от него не зависят.

## Результаты локальной проверки

В финальном наборе 76 тестов: прежние 23 сценария и новые проверки очереди, HTTP-ограничений, DOMParser, планировщика, миграции, маршрута прокси и жизненного цикла. Все прошли. Дополнительно выполнены compileall, bash -n и git diff --check.

На отдельной копии рабочей SQLite проведена миграция с точным сравнением всех старых строк: subscriptions 3, seen 228, settings 3, notifications 36, members 0, invites 1 — всё сохранилось. Проверка integrity_check успешна. Боевой токен и ID в тестовые отчёты не включались.

Факт локальной установки, коммит и путь резервной копии записываются установщиком в `data/deployment.json`. Текущее состояние после запуска проверяется через `avito-service status`, `fetch_metrics` и журнал Application ready. Это не заменяет длительное наблюдение и условный пилот другого источника.

## Продолжение после первого развёртывания

Владелец уточнил, что сторонние API/webhook не используются. Подготовка внешнего адаптера отменена: сторонних интеграций и их настроек в коде нет. Контракт Source сохраняется как архитектурная граница.

Оставшаяся работа переведена в локальный суточный эксперимент. Добавлены независимые source_observations, фиксированные окна studies, пассивные замеры состояний и автоматически формируемый отчёт. Измерение не выполняет новых сетевых запросов. В отчёте отдельно учитываются исходные снимки, отсутствие наблюдателя и изменение фильтров; при отсутствии выборки SLA не вычисляется. Подробности — в local-study.md.

Повторные HTTP 429 дополнительно останавливают автоматические обращения после второй попытки до ручного действия владельца. Ранее сохранённый cooldown учитывается, повторный запуск приложения не обнуляет ограничения.

Сравнение с альтернативным поставщиком исключено из текущего объёма по решению владельца. Суточный результат остаётся незавершённым до фактического окончания измерения; программная подготовка и запуск не выдаются за его результат.

Проверка продолжения: 94 теста прошли, включая восстановление эксперимента, пропущенное время, изменённые фильтры, исключение исходных снимков из задержек, отказ экспорта отчёта и остановку по истории двух 429. Миграция на копии текущей рабочей базы сохранила все существующие строки, в том числе items/outbox/source_state/fetch_metrics. Сторонний адаптер отсутствует.

При повторном локальном развёртывании обнаружено, что launchctl bootout возвращает управление до освобождения OS lock старым процессом. Установщик теперь ждёт штатного завершения до 25 секунд и прекращает установку при таймауте, сохраняя защиту от второго экземпляра. Проверка расширена до 96 проходящих тестов. Начало уже созданного наблюдения сохраняется, время без наблюдателя попадает в UNOBSERVED.
