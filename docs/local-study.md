# Суточное наблюдение локального канала

Сторонние API и webhook не используются по решению владельца. Следующий этап ревью выполняется на локальном браузерном канале: нужно измерить его фактическую доступность, задержки и признаки пропусков. Без независимой контрольной выборки нельзя доказать полноту объявлений или сравнить скорость с другим каналом.

## Как выполняется наблюдение

```sh
uv run avito-study start --hours 24
uv run avito-study report
uv run avito-study report --json
```

Запуск разрешён при наличии активных подписок. Одновременно допускается одно наблюдение local_browser. Фильтры фиксируются на старте: города, разделы, модели, цены и исключения. Изменение фильтров во время эксперимента отмечается в отчёте как нарушение сопоставимости.

Наблюдатель работает внутри уже запущенного приложения. Он читает SQLite и состояние источника раз в минуту и при изменении состояния. Он **не открывает страниц и не увеличивает частоту запросов к Авито**. Ограничения, ручная пауза и закрытие браузера продолжают действовать.

После окончания окна приложение автоматически создаёт `data/studies/<id>/report.md` и `report.json`. Если компьютер/приложение выключены, отчёт формируется при следующем запуске, а пропущенное время отражается как UNOBSERVED. Указанное время окончания не является обещанием 24 часов непрерывной работы источника.

## Что измеряется

- HTTP-коды и количество обычных опросов, удачные снимки и возможные разрывы ID-overlap.
- Состояния ACTIVE, COOLDOWN, WAITING_FOR_USER, DEGRADED, PAUSED, STOPPED, IDLE; отдельно FILTERS_CHANGED и UNOBSERVED.
- Независимые наблюдения ID в source_observations. Они сохраняются и для объявлений, ранее попавших в общий seen.
- Публикация → первое обнаружение подходящего свежего объявления, обнаружение → подтверждённый Telegram, публикация → подтверждённый Telegram.
- p50/p95, размер выборки и доля подтверждённых доставок ≤60 секунд.

Первый успешный снимок города — исходный: объявления могли появиться задолго до наблюдателя. Эти ID исключены из расчётов задержек. Пустой исходный снимок тоже фиксируется: последующие реальные объявления считаются новыми. Время публикации отсутствует — метрика с публикацией не выдумывается.

Подтверждённая доставка считается один раз на объявление, по первому успешному получателю. `/health` ранее считал доставки получателям; это другой знаменатель, поэтому цифры могут отличаться.

Состояния оцениваются пассивными замерами: одна запись покрывает максимум 120 секунд до следующей. Более длинные разрывы относятся к UNOBSERVED. Это оценка доступности наблюдателя и режима сборщика, а не точное измерение доступности сайта.

## Повторные ограничения

Первая 429 запускает cooldown минимум на 15 минут с учётом Retry-After. Вторая подряд 429 переводит источник в WAITING_FOR_USER: автоматических попыток больше нет даже после истечения паузы. Счётчик переживает перезапуск и учитывает историю предыдущей установленной версии. Успешная выдача сбрасывает счётчик.

Ручное /resume может разрешить новую попытку только после обязательного срока ожидания. /unblock открывает проверку только по запросу владельца. Капча решается человеком. Пассивный эксперимент не меняет эти правила и не возобновляет источник самостоятельно.

## Как оценивать результат

Отчёт до конца окна явно помечается промежуточным. Отсутствие успешных выдач означает, что скорость и покрытие не измерены. Нулевая выборка не превращается в «0 секунд» или «100% доставки». Для p95 менее 100 подтверждённых объявлений приводится предупреждение о малой выборке.

Полнота выдачи остаётся неподтверждённой без контрольного канала: ID-overlap указывает только на риск пропусков. Вывод об устойчивости без капчи нельзя делать по одной успешной загрузке. Если источник остановлен защитой всю смену, результат эксперимента — недоступность локального мониторинга в этих условиях.

Отчёты и резервные копии находятся в игнорируемом Git каталоге data. Токен, cookies, профиль браузера и идентификаторы получателей в отчёт не включаются.
