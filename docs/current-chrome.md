# Подключение к уже открытому обычному Chrome

`chrome_extension` подключает монитор к текущему Google Chrome, в котором пользователь уже вошёл
в Авито. Перезапуск Chrome, экспорт cookies, копирование системного профиля и debugging-порт не нужны.
Существующие `managed` и `cdp_attach` остаются самостоятельными режимами.

## Почему нужен другой транспорт

Обычный Chrome не предоставляет CDP endpoint. Начиная с Chrome 136 удалённая отладка системного
профиля ограничена самим Chrome: [официальное изменение](https://developer.chrome.com/blog/remote-debugging-port).
Поэтому `cdp_attach` невозможно включить задним числом для обычного работающего окна.
Расширение использует официальный [chrome.scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting)
для фиксированных операций с DOM в одной выделенной вкладке текущего браузера. Это отдельный
транспорт, а не подмена названия CDP и не перенос сессии в другой профиль.

## Установка

```bash
uv sync --frozen --extra experimental
uv run avito-extension-setup
```

Команда готовит папку `data/chrome-extension`. В ней находятся manifest, worker, popup,
те же функции извлечения объявлений, что у Scraper, и локальные параметры подключения.
`settings.js` и `data/extension-bridge/pairing-token` содержат случайный ключ сопряжения и имеют
права 0600. Их нельзя публиковать; каталог `data` исключён из Git.

В **уже открытом Chrome**:

1. Откройте `chrome://extensions` и включите «Режим разработчика».
2. Нажмите «Загрузить распакованное расширение» и выберите папку, напечатанную командой.
3. В меню расширений откройте «Avito Monitor — текущий Chrome» и нажмите «Подключить этот Chrome».

Расширение локальное, не из магазина. Перед установкой нужно согласие владельца браузера:
оно получает доступ к страницам `https://avito.ru/*` и `https://www.avito.ru/*`, локальному боту,
а также API вкладки/навигации, необходимые для работы выделенной вкладки. Разрешения `cookies`,
`debugger`, доступ ко всем сайтам и выполнение произвольного JavaScript от бота не запрашиваются.
Расширение не считывает и не пересылает пароли, cookies или заголовки авторизации.

В `.env`:

```dotenv
BROWSER_SESSION_MODE=chrome_extension
BROWSER_ENGINE=playwright
EXTENSION_BRIDGE_PORT=9233
STARTUP_DIAGNOSTICS=1
```

`BROWSER_ENGINE` используется в прежних браузерных режимах; для расширения фактический транспорт
в health/метриках обозначается `chrome_extension`. DirectProxy бота в этом режиме не запускается.
Сеть и сессия принадлежат пользовательскому Chrome; внешний IP считается неизвестным.

Если сервис раньше отключали вместе с автозапуском, перед установкой включите его:

```bash
launchctl enable "gui/$(id -u)/local.avito-monitor"
uv run avito-service install
uv run avito-diagnostics --startup
```

## Как работает соединение

- Сервер слушает только `127.0.0.1:9233`. Принимается WebSocket с origin расширения Chrome
  и совпадающим случайным ключом в первом сообщении, без ключа в URL. Вторая одновременная
  сессия отклоняется. Обычная веб-страница подключиться не может.
- Пользователь включает соединение кнопкой расширения. Создаётся одна пустая выделенная вкладка
  **в том же профиле Chrome**, что и текущий аккаунт. Естественные cookies остаются внутри браузера.
  Создание/сопряжение вкладки не обращается к Авито.
- Бот выполняет навигацию только по каталогу и только когда её разрешает общий планировщик.
  Извлечение DOM и один `fetch` используют те же функции Scraper и прежний AccessCoordinator.
- Сохраняются Retry-After, backoff, защита от старого DOM, проверка точного поиска, Outbox и
  независимость Telegram. Расширение не подтверждает доступ автоматически по факту подключения.
- HTTP-статус и Retry-After главной навигации пассивно наблюдаются через `webRequest`;
  неизвестные значения остаются неизвестными. Локальные чтения DOM не создают запросов.
- При переподключении используется прежний id выделенной вкладки в `storage.session`.
  Чужие вкладки не переиспользуются. При остановке бота Chrome и его вкладки не закрываются.
- Установленный worker поддерживает соединение heartbeat и ограниченными повторами локального
  подключения; они не обращаются к Авито. Сопряжение с браузером ожидается до 20 секунд,
  после чего Monitor продолжает ограниченные попытки восстановления; Telegram остаётся доступен.
- Дополнительная загрузка фотографий через API браузера в этом режиме отключена. Telegram
  доставляет карточки через существующий механизм отправки без необязательного фото.
- Если пользователь перезапустит/перезагрузит расширение и Chrome очистит `storage.session`,
  прежнюю вкладку нельзя безопасно отождествить с новой; будет создана новая пустая выделенная вкладка.
  Старые пользовательские вкладки при этом остаются открыты.

## Отключение и откат

Нажмите «Отключить расширение» или остановите сервис. Удаление расширения выполняется через
`chrome://extensions`. Chrome и аккаунт Авито остаются у пользователя. Для возврата к прежнему
режиму укажите `managed` или `cdp_attach` в `.env`, с их прежним движком/профилем; SQLite не удаляется.
Отдельного обхода ограничений для расширения нет: смена транспорта не снимает действующий срок.

## Проверка

`tests/test_extension_session.py` проверяет origin/token, единственное соединение, разрешённые
домены/операции, закрытие транспорта, упаковку и права файлов. Интеграционный тест запускает
отдельный Chromium с настоящим расширением и локально перехваченными HTML-фикстурами: первая
навигация, light_fetch, 429 с проверкой/Retry-After, повторное чтение DOM без запроса, сохранность
другой вкладки и переподключение без навигации. Реальный Авито в pytest не используется.

Полный локальный прогон: **289 passed in 90.94s**, включая настоящий Chromium с расширением.
`uv sync --frozen --extra experimental`, compileall, `uv pip check`, `git diff --check` и сборка wheel прошли.
Ресурсы расширения включены в wheel, локальные ключи сопряжения в пакет не попадают.
