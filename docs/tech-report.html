Авито-монитор: как устроен и почему его блокируют

Личный Telegram-бот, который присылает новые объявления Авито о комплектующих и компьютерах в Казани. Ниже — архитектура, как устроен опрос, что показали замеры и где упираемся в защиту Авито.

Задача

  • Следить за разделами «Товары для компьютера» и «Настольные компьютеры» в одном или нескольких городах.
  • Пользователь задаёт запросы: раздел (видеокарты, процессоры, ПК…), модель, цену, слова-исключения.
  • Новое подходящее объявление должно прийти в Telegram как можно быстрее. Исходная цель — 15–30 секунд.
  • Запуск на обычных домашних ПК: VPS и VPN Авито блокирует сразу, поэтому нужен домашний IP.

МодульЧто делает
scraper.pyЗапускает настоящий Google Chrome через Playwright (channel="chrome", окно свёрнуто, без флага --enable-automation). Если Chrome нет — встроенный Chromium. Достаёт объявления из DOM и точное время публикации из служебного JSON страницы.
monitor.pyПо кругу опрашивает ленты городов в пределах лимита загрузок в минуту; отмечает просмотренные ID; при блокировке разворачивает окно браузера, пишет в Telegram и ждёт, пока человек пройдёт капчу.
matcher.pyНормализует названия (RTX3060Ti = ртх 3060 ти, 1660S = 1660 super), определяет раздел объявления (видеокарта, процессор, память, мать, накопитель, БП, охлаждение, корпус, ПК), сверяет с запросами.
bot.py, ui.pyИнтерфейс на inline-кнопках: меню, мастер запроса, карточки, выбор городов, доступ по ссылке-приглашению, уведомления с фото.
direct_proxy.pyЛокальный HTTP CONNECT-прокси: если на ПК включён VPN в режиме TUN, трафик к Авито уходит напрямую через домашнюю сеть (DNS через DoH, сокет привязан к интерфейсу).
start.sh / start.batУстановка (uv, Python, Chromium), первичная настройка (токен, город, VPN) и запуск с автоперезапуском.

Как идёт опрос

  1. При старте Chrome открывает ленту города полной загрузкой: /kazan/bytovaya_elektronika?s=104 (раздел «Электроника», сортировка по дате). Так проходит JS-проверка Авито (код 439, proof-of-work), если она есть.
  2. Дальше страница больше не перезагружается. Каждую итерацию из неё выполняется fetch(url, {credentials: "include"}) к той же ленте, ответ разбирается DOMParser. Это один HTTP-запрос вместо ~350 при полной загрузке (из них ~60 на домены Авито).
  3. Из 50 объявлений ленты остаются только разделы tovary_dlya_kompyutera и nastolnye_kompyutery (по адресу объявления). Одна лента «Электроника» на город вместо двух отдельных — вдвое меньше запросов.
  4. Новые ID сверяются с запросами, подходящие уходят в Telegram.
  5. Если ответ 403/429 или заголовок «Доступ ограничен» — полная загрузка страницы, чтобы показать капчу, и ожидание человека.
// упрощённо: лёгкий опрос из уже открытой страницы Авито
const r = await fetch(url, {credentials: 'include', cache: 'no-store'});
const doc = new DOMParser().parseFromString(await r.text(), 'text/html');
const items = [...doc.querySelectorAll('[data-marker="catalog-serp"] [data-marker="item"]')];
// точное время: script[type="mime/invalid"] → объекты с id и sortTimeStamp

Лимит загрузок задаётся в .env (REQUESTS_PER_MINUTE, сейчас 2) и делится между городами: один город при 2/мин проверяется раз в ~30 с. Ночью — 1 в минуту.

Блокировки

Авито отвечает на подозрительные запросы тремя способами:

ОтветСтраницаКак проходится
439«Доступ ограничен: проверка безопасности»JS proof-of-work, браузер проходит сам за пару секунд. Простой HTTP-клиент (даже с TLS-отпечатком Chrome) не проходит.
429 / 403«Доступ ограничен: проблема с IP»Кнопка «Продолжить» → капча (GeeTest или hCaptcha). Проходит человек.
—Кнопка «Продолжить» не реагируетБыло в Chromium из Playwright с флагом --enable-automation; в установленном Google Chrome без этого флага капча показывается.

Выводы и гипотезы

  • Частота важна, но не решает. При ~12 загрузках в минуту блок через ~5 мин. При 2–4 в минуту — всё равно блок, только позже (2–24 мин).
  • После пометки капча даёт пропуск ровно на 20 минут (13:04 → 13:24 → 13:44), независимо от частоты.
  • Пометка привязана к профилю браузера (cookies), а не только к IP. Помеченный профиль блокируется сразу на любом IP; чистый профиль проходит, пока с ним не начнёт работать бот.
  • Вероятная причина: Авито распознаёт управление браузером через Playwright (подключение по протоколу отладки Chrome) и/или поведенческий паттерн — одна страница без действий пользователя и периодические fetch HTML-документа из неё.
  • Частые перезапуски бота (каждый — новая полная загрузка) явно ускоряли блокировки.

Обход защиты (автоматическое решение капчи, подмена отпечатков, ротация профилей) в проекте не делался сознательно. Сейчас бот работает в режиме «бот + человек»: когда Авито просит проверку, бот пишет в Telegram, и капчу проходит пользователь.

Открытые вопросы

  • Есть ли у Авито режим работы, при котором такой мониторинг допустим без капчи — например, при заметно меньшей частоте или в рамках официальных инструментов.
  • Насколько быстро приходят пуш-уведомления сохранённого поиска Авито по сравнению с измеренными ~100 с — если сопоставимо, это вариант без автоматизации браузера.
  • Как ведёт себя один бот на других домашних ПК (другой IP и отпечаток) при 1–2 загрузках в минуту на протяжении нескольких часов.

Стек

Python 3.12 (uv), Playwright 1.64 + Google Chrome, aiogram 3.31 (Telegram Bot API 10.3), SQLite, httpx. Тесты — pytest (22 теста: поиск, разделы, интерфейс, доступ, лимиты). Проект — git-репозиторий, запуск через start.sh / start.bat.
