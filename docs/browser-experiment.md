# Сравнение браузерных режимов

По умолчанию остаются `BROWSER_ENGINE=playwright`, `FETCH_MODE=light_fetch`, `BROWSER_CHANNEL=chrome`, `HEADLESS=0`. Patchright — опциональный эксперимент, а не подтверждённое средство устранения ограничений. Автоматического запуска эксперимента или смены `.env` нет.

## Установка

В `uv.lock` зафиксированы Playwright 1.64.1 и Patchright 1.64.3. Проверена совместная установка на Python 3.12.15: оба используют `pyee>=13,<15` и `greenlet>=3.1.1,<4`. Проверенный браузер на macOS — Google Chrome. API запуска: [асинхронный API Patchright](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright-python#usage); установка браузеров: [Playwright](https://playwright.dev/python/docs/browsers).

Команды из корня проекта одинаковы для терминалов macOS, PowerShell Windows и Linux:

```sh
uv sync --frozen --extra experimental
uv run --extra experimental patchright install chromium
```

Вторая команда ставит управляемый Chromium; используйте его только с явным `BROWSER_CHANNEL=chromium`. Для стандартного `BROWSER_CHANNEL=chrome` нужен установленный Google Chrome. Если Chrome уже есть, повторная установка браузера не требуется. Если его нет:

```sh
uv run --extra experimental patchright install chrome
```

На Linux системные библиотеки для управляемого Chromium устанавливаются так; пакетный менеджер может запросить права администратора:

```sh
uv run --extra experimental patchright install --with-deps chromium
```

Для исходного Playwright с управляемым Chromium:

```sh
uv run playwright install chromium
```

Не меняйте канал автоматически после ошибки запуска. Неисправный/занятый профиль или отсутствующий Chrome требуют исправления причины. Для Linux с `HEADLESS=0` нужна графическая сессия. Автоматические стартовые скрипты сохраняют установленные экспериментальные зависимости благодаря `uv sync --inexact`; обычный точный `uv sync --frozen` удалит Patchright. Повторно установите extra перед его использованием. Сам `uv run --extra experimental` не включает Patchright: движок выбирается настройкой приложения.

## Профили и сохранение состояния

| Движок | Chrome | Chromium |
|---|---|---|
| Playwright | `data/browser-profile-chrome` (прежний путь) | `data/browser-profile` (прежний путь) |
| Patchright | `data/browser-profile-patchright-chrome` | `data/browser-profile-patchright` |

Cookies между каталогами не копируются. Новый профиль может потребовать отдельной ручной проверки. Одновременно разрешён один движок: основной процесс и `avito-unblock` защищены прежним `bot.lock`, а браузерный слой дополнительно держит общий `browser.lock`.

`source_id=local_browser`, база, `seen`, ключ исходного снимка ленты, ограничения всех городов и общий бюджет остаются прежними. Смена движка/режима/канала не разрешает повторный запрос раньше срока и не сбрасывает сохранённые `RATE_LIMITED`, `VERIFICATION_REQUIRED`, `ACCESS_DENIED` и уровень локальной паузы после 429. Закрытый браузер перезапускается автоматически без нарушения сроков; Telegram и доставка продолжают работу.

## Ручное включение и возврат

1. Сохраните текущий отчёт: `uv run avito-metrics --compare > data/comparison-before.json`. На базе старой версии сначала нужно один раз запустить обновлённое приложение с исходными настройками: оно выполнит только добавление столбцов метрик. Отчёт сам базу не мигрирует.
2. Остановите приложение. На macOS: `uv run avito-service stop`; при обычном запуске завершите supervisor через Ctrl+C. Установите extra и нужный браузер командами выше.
3. Вручную задайте в `.env` одну комбинацию. Пример:

   ```env
   BROWSER_ENGINE=patchright
   FETCH_MODE=page_navigation
   BROWSER_CHANNEL=chrome
   HEADLESS=0
   ```

4. Запустите **один** процесс: `uv run --extra experimental avito-supervise`. На macOS вместо этого зарегистрируйте службу: `uv run --extra experimental avito-service install`, затем `uv run --extra experimental avito-service status`. Установка службы сохраняет обычную резервную копию SQLite. Не запускайте supervisor рядом со службой.
5. Проверьте `/health`: там видны движок, канал, режим и прежние ограничения. Сроки ограничений остаются обязательными. Если необходима проверка — решите её в окне Chrome бота (при необходимости после `/unblock`); бот сам продолжит сбор. Не используйте смену режима как способ возобновить ограниченный источник.
6. Для следующей комбинации сначала остановите приложение, затем измените `.env` и повторите запуск. Не запускайте четыре комбинации параллельно.
7. Возврат: остановите приложение, задайте `BROWSER_ENGINE=playwright`, `FETCH_MODE=light_fetch` и прежний `BROWSER_CHANNEL`, затем запустите supervisor или переустановите LaunchAgent. Старый профиль Playwright остаётся на месте. Базу и каталоги `data/` не удаляйте. Удалять экспериментальную зависимость не обязательно.

Сохраняйте одинаковые подписки, города, бюджет, ночной режим, канал, маршрут сети и длительность окон. Не увеличивайте частоту ради накопления выборки. Навигация загружает ресурсы страницы и обычно расходует больше трафика; общий лимит планировщика ограничивает проверки ленты, а не все отдельные ресурсы Chrome.

## Отчёты

```sh
uv run avito-metrics
uv run avito-metrics --compare > data/browser-comparison.json
uv run avito-metrics --events > data/events.csv
uv run avito-metrics --compare --since 1792830000 --until 1792916400
```

`--since` включительно и `--until` исключительно принимают Unix-время. Это границы обнаружения/проверки; более позднее подтверждение доставки относится к исходному обнаружению. Можно читать отдельную копию базы: `--db path/to/bot.sqlite3`. Команды открывают SQLite только для чтения и не запускают браузер.

В `fetch_metrics` добавлены:

- `browser_engine`, `browser_channel`, `fetch_mode`, фактический `actual_mode`;
- `run_id` отдельного запуска браузера, `duration_sec`;
- `request_count`, `transferred_bytes`, `access_limited`;
- `budget_rpm`, `comparison_context`, `operation` (`automatic` / `manual`);
- `is_warmup` (`1` — первая попытка навигации запуска, `0` — повторная проверка, `NULL` — исторический этап неизвестен);
- `restriction_reason` — безопасный код признака ограничения (`http_403`, `http_429`, `http_439`, `captcha_marker`, `challenge_title`, `challenge_text`, `blocked_title`, `blocked_text`), без текста страницы.

HTTP-статус, результат, число объявлений, пересечение снимков и срок паузы сохраняются прежними. Первая попытка навигации каждого запуска отмечается `is_warmup=1` при любом настроенном режиме. В `light_fetch` она имеет `actual_mode=page_navigation`; следующие успешные лёгкие проверки — `actual_mode=light_fetch`. Если первоначальная загрузка не удалась, следующая разрешённая планировщиком попытка навигации уже обычная, с `is_warmup=0` и `actual_mode=page_navigation`: повторные ошибки не прячутся под warm-up. Первое ручное открытие тоже может быть warm-up, но остаётся в ручной статистике.

`duration_sec` измеряет вызов сбора, включая ожидание клиентского каталога, а не время запуска процесса Chrome. После 403/429/439 нет дополнительного чтения DOM для выяснения причины и нет повторной загрузки. HTTP-запрет сохраняет приоритет даже при ошибке чтения заголовков. При ошибке инспекции DOM известный HTTP-статус также не теряется.

`avito-metrics --compare` выдаёт `schema_version=2`. Структура JSON изменилась: потребителям прежних верхних `checks`/`duration_sec` внутри группы нужно читать вложенные показатели.

- `groups`: четыре выбранные конфигурации. `configuration_totals` включает все их автоматические проверки и всю записанную нагрузку, включая warm-up и старые записи с неизвестным этапом. `warmup` отдельно показывает первоначальные загрузки, длительность и трафик. `regular_by_actual_mode` разделяет обычные проверки по фактическому механизму. `unknown_phase` содержит исторические записи, которым нельзя достоверно назначить этап.
- `mechanisms`: производительность повторных проверок по `browser_engine` + `actual_mode`; warm-up, ручные проверки и неизвестный исторический этап исключены. Задержка доставки здесь тоже относится только к обычному первоначальному обнаружению соответствующим механизмом. Нельзя сопоставлять первую навигацию с обычным fetch.
- `mechanisms[].cohorts`: отдельные наборы с одинаковыми хешем контекста, фактическим бюджетом, каналом и городом. При `mixed_contexts=true` общие `totals` объединяют несколько наборов, поэтому для сравнения выбирайте соответствующие `cohorts` и одинаковые временные окна. `context_complete=false` означает неполную атрибуцию. Хеш проверяет сохранённые настройки, но не доказывает неизменность фактического подключения Wi-Fi/IP — это условие нужно соблюдать вручную.
- `total_load`: все записанные обращения, включая ручные и исторические; `automatic_load` и `manual_load` показывают их отдельно. Это измеренная нагрузка во время сбора, а не полный расход сетевого интерфейса.

Показатели включают долю `ok`/`no_results`, ограничения, сумму наблюдений объявлений, уникальные ID, p50/p95 длительности, трафик и задержку доставки. Пустая выборка имеет `success_share=null`. Для неизвестного измерения сохраняется `NULL` и выводится `null`; измеренный ноль остаётся нулём. `measured_checks` показывает, скольким проверкам соответствует сумма, поэтому частичное измерение не выглядит полным. Отрицательные задержки при коррекции часов исключаются; `invalid_delivery_timestamps` сообщает их число.

`windows` разделяет последовательные участки одного запуска с одинаковыми контекстом, бюджетом и каналом: A → B → A остаются тремя участками. Отсчёт времени до первого ограничения идёт от начала первой наблюдаемой проверки участка, включая warm-up, и не сбрасывается параметром `--since`. Отчёт читает более раннюю историю и может показать первое ограничение, которое было до выбранного диапазона; `selected_checks` содержит только выбранные проверки. Если нет исходной длительности или `run_id`, `started_at` и `seconds_to_first_restriction` остаются `null`, вместо предположения о нулевой длительности.

При отсутствии ограничения `seconds_to_first_restriction=null` и `censored=true`. Это незавершённое наблюдение, а не доказательство стабильности на малой выборке. Наблюдаемый промежуток между проверками не доказывает непрерывную работу приложения. Хеш контекста не раскрывает запросы подписок; ручные открытия страницы исключены из автоматических окон.

Каждое новое сохранённое объявление несёт метаданные первоначального обнаружения внутри прежнего payload. Изменение настроек до отправки сообщения не меняет атрибуцию доставки. CSV содержит фактический `actual_mode`, этап `is_warmup` и время `published_at`, `first_seen_at`, `delivered_at`; ID чатов не экспортируются. Исходные timestamps публикации доступны также в `source_observations`. Исходный снимок не отправляется в Telegram и не участвует в статистике задержки доставки. Гарантия прежней очереди — at-least-once; изменение режима само по себе дублей не создаёт.

## Пределы измерений

Сетевые счётчики пассивно читают CDP `Network.requestWillBeSent` и `Network.loadingFinished` основной страницы за время вызова сбора. `encodedDataLength` — приблизительный объём завершённых ответов, а не точный расход интерфейса: он не включает TLS/прокси накладные расходы. Ресурсы, завершившиеся после окончания вызова, фоновые запросы между проверками, отдельный `ctx.request` для фотографий и трафик Telegram не входят в эти показатели. Кэш, redirects и фоновые ресурсы влияют на сравнение; CDP не сохраняет адреса, заголовки или тела. При недоступности или отключении CDP значения `null`; отсутствующий/некорректный `encodedDataLength` делает объём неизвестным до следующего запуска, вместо подстановки нуля. Доступность измерений показана отдельным счётчиком. Полные HTML, cookies, токены и личные сообщения в новые метрики не попадают.

Исторические метрики не приписываются движку задним числом (`unattributed_checks`). Старые записи с известным движком, но без `is_warmup`, остаются в `unknown_phase` и `configuration_totals`, а в сравнении повторных проверок не используются. Чтение отчёта поддерживает и предыдущую браузерную схему без её миграции; обновлённое приложение только добавляет два столбца и не переписывает прежние строки. `sortTimeStamp` берётся из Авито и не всегда доступен; это не измерение момента фактического появления карточки в поиске. Задержки зависят от часов компьютера, фильтров и доступности источника. Квантили доставки считают получателей. Последовательные окна в разное время не дают причинного доказательства преимущества движка.

Локальные тесты проверяют совместимость API и сохранение политики, но не прогнозируют частоту 403/429 на настоящем Авито. Подтверждение преимуществ требует длительного ручного наблюдения с достаточной выборкой. Windows/Linux описаны по API библиотек; выполнение именно на этих ОС требует отдельной проверки. Нет автоматического решения капчи, ротации IP, переноса cookies, массового создания профилей или автоматического обхода сохранённых ограничений.

## Уточнённая диагностика служебных страниц

HTTP 403/429/439 имеет приоритет над содержимым документа. HTTP 200 с отдельным captcha-маркером, iframe известного провайдера или текстом проверки без каталога классифицируется как `CHALLENGE`; подтверждённые признаки запрета без каталога — `BLOCKED`. При одновременном заголовке запрета и captcha-маркере выбирается `CHALLENGE`. Нормальная пустая выдача требует маркера пустых результатов либо каталога с соответствующим текстом. Одна фраза «Ничего не найдено» в неизвестном HTML даёт `PARSE_CHANGED`.

Текст объявлений и неактивные script/style/template/noscript не служат доказательством блокировки. Название поискового запроса в заголовке не превращает корректный каталог в страницу проверки. Эти правила проверены на локальных модельных фикстурах; они не покрывают все будущие варианты страниц Авито. При неизвестной разметке сохраняется безопасный `PARSE_CHANGED` и прежняя пауза `DEGRADED`, без дополнительных обращений для диагностики. Ошибка записи безопасного диагностического образца не меняет уже распознанный статус источника.

В этой доработке изменены `src/avito_bot/scraper.py`, `src/avito_bot/metrics.py`, `src/avito_bot/db.py`, `src/avito_bot/monitor.py`, `tests/test_browser_modes.py`, `tests/test_browser_metrics.py`, `README.md`, этот документ; добавлены фикстуры `blocked-ip.html`, `challenge-frame.html`, `challenge-browser.html`, `blocked-with-captcha.html`, `unknown-empty-text.html`, `empty-marker.html`, `catalog-service-words.html` в `tests/fixtures/`. Контракт Source, Telegram, фильтры, Outbox, ограничения и процедуры переключения движков остаются прежними.

Проверка этой доработки на macOS ARM64 / Python 3.12.15: **200 passed** с extra `experimental`; дополнительно **6 passed** для обоих движков на управляемом Chromium, включая служебные страницы, DirectProxy и APIRequestContext. Успешны все команды проверки из задания, `uv pip check` и сборка wheel/sdist. Рабочая `.env`, пользовательская база и LaunchAgent не переключались; настоящее Авито и длительное наблюдение не запускались. Windows/Linux и частота ограничений на реальном источнике требуют отдельного испытания.
